# AFR functional audit — 2026-09-19

## Scope

This audit treated Agent Flight Recorder as a working local-first product. It
covered the FastAPI backend, SQLite persistence, replay policy boundary, Python
SDK and decorators, CLI/export paths, seeded demo, smoke test, React UI,
packaging, Docker configuration, CI, dependency advisories, public claims, and
license metadata.

The audit was source review plus executable validation. It was not an external
penetration test, browser end-to-end test, or high-concurrency load test.

Severity labels:

- **P1:** breaks a documented/default path, risks silent data loss, or carries a
  known security advisory.
- **P2:** produces materially wrong behavior outside the default path or removes
  an important verification boundary.
- **P3:** limitation or hardening gap that should be explicit and tracked.

## Findings and disposition

## Replay and safety boundary

The default is conservative: replay is disabled unless explicitly enabled;
`dry_run` skips all tools; `mock_tools` mocks all tools; unknown tool policies
fall back to `side_effecting`; `requires_approval` remains blocked in the
side-effect mode without approval. The backend only returns a plan and recorded
state. User code runs in the SDK process, and the SDK invokes a handler only for
an exact server status of `ready`.

Redaction runs before backend persistence and also in the SDK. It covers common
secret-bearing keys and common token/key patterns. This remains best-effort
scrubbing rather than a confidentiality guarantee, which matches the public
claims.

API authentication is optional for the zero-config loopback use case. When a
token is configured, both root and `/api` mounts are protected and comparisons
use `hmac.compare_digest`. Docker publishes to host loopback by default. Any
non-loopback deployment still needs a token, TLS at a reverse proxy, database
file protection, and normal operational controls.

## Known limitations to track

1. **Replay handler timeout is not process isolation (P3).** A timed-out handler
   runs in a Python thread. AFR reports the timeout and stops waiting, but Python
   cannot forcibly terminate a running thread; handler code may continue until
   it returns. Side-effecting replays should run in a separate process or worker
   if hard termination is required.
2. **Checkpoint creation spans multiple transactions (P3).** The state event,
   checkpoint event, and checkpoint row are separate writes. A crash or storage
   failure between them can leave a timeline event without a matching
   checkpoint row. Making the operation atomic requires a repository-level
   transaction that covers all three writes.
3. **State reconstruction has a one-million-event internal ceiling (P3).** Runs
   with more than one million state snapshots can reconstruct an incomplete
   state without a truncation marker. Normal API export no longer has the
   10,000-event truncation, but the internal state fold should eventually use
   cursor pagination or an explicit limit error.
4. **FastAPI's test client emits an upstream transition warning (P3).** The
   pinned FastAPI/Starlette stack warns that its `httpx` TestClient path is
   deprecated in favor of `httpx2`. AFR previously removed `httpx2` during a
   dependency-confusion containment review. Do not re-add it blindly; resolve
   the warning by verifying the upstream package and migration path first.
5. **No browser automation or load test is present (P3).** The UI compiles and
   its API client was reviewed, but interactive browser behavior and sustained
   concurrent ingestion were not exercised in this audit.

## Verification receipt

The repaired tree passed:

- `make test`: 126 tests passed; one upstream TestClient deprecation warning.
- default-config live smoke test: health, license, create, append, checkpoint,
  state reconstruction, replay-disabled outcome, and end-run all passed.
- default-config demo seed: returned HTTP 201 and created the canonical failed
  run with two checkpoints.
- `python -m compileall` across backend, SDK, CLI, examples, scripts, and the
  Codex adapter.
- `python scripts/check_claims.py`.
- clean UI install, TypeScript check, Vite production build, and `npm audit`.
- `pip-audit` after the AnyIO update: no known third-party vulnerabilities.
- wheel builds for `afr-backend`, `afr-sdk`, and `afr-cli`.
- targeted repository secret-pattern scan: matches were intentional redaction
  fixtures and test keys; no live credential was identified.

Advisory databases change over time. The CI audit gate and dependency update
process should remain active.
